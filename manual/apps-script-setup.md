# Настройка Google Apps Script

Инструкция для шага 2.2: как подключить скрипт приёма снимка к Google Таблице и проверить, что он отвечает. Кода сайта и макроса здесь нет — только сервер.

Что понадобится:

- аккаунт Google, под которым будет жить Таблица;
- файлы `apps-script/Code.gs`, `apps-script/Validate.gs`, `apps-script/appsscript.json` из репозитория;
- менеджер паролей (или генератор случайных строк) — для двух ключей;
- `curl.exe` — в Windows 10 и 11 он уже есть в системе.

На экране будут английские надписи, в скобках даю русский смысл.

## Шаг 1. Создать Таблицу

1. Откройте [sheets.new](https://sheets.new) (или Google Диск → Создать → Google Таблицы).
2. Назовите файл «Проверка знаний — данные».
3. Больше в Таблице ничего создавать вручную не нужно: листы «Снимок», «Снимок_пред», «Мета», «Журнал» появятся сами.

## Шаг 2. Вставить код

1. В Таблице: «Расширения» → «Apps Script» («Extensions» → «Apps Script»).
2. Удалите содержимое файла `Код.gs` (`Code.gs`), который там уже есть, и вставьте целиком `apps-script/Code.gs`.
3. Слева у значка «+» выберите «Скрипт» («Script»), назовите его `Validate` и вставьте туда `apps-script/Validate.gs`.
   Имя файла важно только для вас — важен сам код.
4. Сохраните проект (значок с дискетой или Ctrl+S). Название проекта — например «Проверка знаний — публикация».

## Шаг 3. Показать и заполнить манифест

1. Слева выберите «Настройки проекта» («Project Settings»).
2. Поставьте галочку «Показывать файл манифеста appsscript.json в редакторе» («Show "appsscript.json" manifest file in editor»).
3. Вернитесь в «Редактор» — появился файл `appsscript.json`. Замените его содержимое на текст из `apps-script/appsscript.json`.
4. Сохраните. Там уже задано: часовой пояс `Etc/UTC`, современный движок V8, запись ошибок в журнал Google, веб-приложение работает от вашего имени и доступно всем, кто знает адрес.

## Шаг 4. Создать листы

1. В редакторе вверху выберите функцию `setupSheets` и нажмите «Выполнить» («Run»).
2. Google попросит разрешения — согласитесь: «Просмотреть разрешения» → выберите аккаунт → «Дополнительные настройки» → «Перейти на страницу проекта (небезопасно)» → «Разрешить». Это стандартный экран для ваших собственных скриптов.
3. Вернитесь в Таблицу и обновите страницу: должны появиться листы «Снимок», «Снимок_пред», «Мета», «Журнал» с заголовками.

## Шаг 5. Задать два секретных значения

1. В редакторе скрипта: «Настройки проекта» → раздел «Свойства скрипта» («Script Properties») → «Добавить свойство» («Add script property»).
2. Добавьте два свойства. Значения — случайные строки длиной от 32 символов, лучше сгенерировать в менеджере паролей:
   - `PUBLISH_KEY` — ключ публикации (им будет пользоваться макрос Excel);
   - `HASH_SECRET` — секрет для хеширования кодов доступа (в Таблицу попадают только хеши).
3. Нажмите «Сохранить свойства» («Save script properties»).
4. Сразу сохраните оба значения в менеджере паролей. В репозиторий, чаты и документы их вставлять нельзя.

## Шаг 6. Развернуть как веб-приложение

1. В редакторе: «Развернуть» («Deploy») → «Новое развёртывание» («New deployment»).
2. Слева у шестерёнки выберите тип «Веб-приложение» («Web app»).
3. Заполните:
   - «Описание» — например «Публикация снимка»;
   - «Выполнять от имени» («Execute as») — «Я» (`Me`), это ваш аккаунт;
   - «Кто имеет доступ» («Who has access») — «Все» (`Anyone`).
4. Нажмите «Развернуть» и скопируйте «URL веб-приложения» («Web app URL»). Он заканчивается на `/exec`.
5. Адрес сохраните у себя. Если потеряете — его видно в «Управление развёртываниями».

## Шаг 7. Проверить, что адрес живой

1. Вставьте адрес в браузер и допишите `?action=ping`, получится примерно:
   `https://script.google.com/macros/s/…/exec?action=ping`
2. Ожидаемый ответ: `{"ok":true,"schema_version":1,"published_at":null}`.
   `published_at` равен `null`, пока не было ни одной публикации.
3. Любой другой адрес того же скрипта без `action=ping` должен ответить `{"ok":false,"error":"not_found"}` — это нормально, данные сотрудников в браузере не отдаются.

## Шаг 8. Отправить тестовый снимок

Отправляется файл `tests/fixtures/snapshot.sample.json` — там только вымышленные данные.

1. Откройте командную строку (`cmd`) в папке проекта.
2. Задайте адрес и ключ на текущую сессию:

   ```
   set APPS_SCRIPT_URL=https://script.google.com/macros/s/ВАШ_АДРЕС/exec
   set PUBLISH_KEY=ваш-ключ-из-шага-5
   ```

3. Отправьте снимок:

   ```
   powershell -ExecutionPolicy Bypass -File tests\send-test-snapshot.ps1
   ```

4. Ожидаемый ответ: `{"ok":true,"count":3,"published_at":"…"}`.
5. Проверка отказа:

   ```
   powershell -ExecutionPolicy Bypass -File tests\send-test-snapshot.ps1 -WrongKey
   ```

   Ожидаемый ответ: `{"ok":false,"error":"forbidden"}`, а данные в Таблице не меняются.

Скрипт не печатает значение ключа и удаляет временный файл с телом запроса после отправки.

## Шаг 9. Что должно появиться в Таблице

- «Снимок» — 3 строки: `code_hash` (длинная строка из hex-символов), `internal_id` (`E0001`, `E0002`, `E0003`), `json` (карточка сотрудника без поля `code`). Открытых кодов доступа в таблице нет и быть не должно.
- «Мета» — одна строка: время публикации, время формирования снимка, версия схемы `1`, количество сотрудников `3`, настройки в виде JSON.
- «Журнал» — строка с действием `publish`, результатом `ok` и количеством `3`.
- «Снимок_пред» — при первой публикации пуст, при второй и следующих содержит предыдущий снимок.

Повторная отправка того же снимка заменяет «Снимок» и копирует прежнее содержимое в «Снимок_пред».

## Важные предупреждения

1. **Повторное развёртывание.** Если будете менять код, используйте «Управление развёртываниями» → значок карандаша у текущего развёртывания → «Изменить» → «Развернуть». Если нажать «Новое развёртывание», получится **новый адрес**, и макрос со старым адресом перестанет работать.
2. **Смена `HASH_SECRET`.** После смены секрета все ранее записанные хеши кодов становятся недействительными: до следующей публикации старые записи не совпадут с новыми. Меняйте его только вместе с перепубликацией снимка.
3. **Ключи живут только в свойствах скрипта.** В репозитории, README, чатах и скриншотах их быть не должно.
4. **Доступ «Все».** Любой, кто знает адрес, может вызвать `ping`. Публикация требует ключ, поэтому без него данные не изменить.

## Если что-то не работает

| Ответ сервера | Что это значит | Что делать |
|---|---|---|
| `{"ok":false,"error":"bad_request"}` | Тело запроса не JSON | Проверьте, что отправляете файл целиком (`--data-binary @файл`) |
| `{"ok":false,"error":"server_not_configured"}` | Не заданы свойства скрипта | Вернитесь к шагу 5 |
| `{"ok":false,"error":"forbidden"}` | Неверный ключ публикации | Сверьте `PUBLISH_KEY` со свойством скрипта |
| `{"ok":false,"error":"invalid_snapshot"}` | Снимок не прошёл проверку | Смотрите `details`: там номер элемента и имя поля, без персональных данных |
| `{"ok":false,"error":"busy"}` | Идёт другая публикация | Повторите через минуту |
| `{"ok":false,"error":"not_found"}` | Запрос не на `action=ping` | Для проверки нужен именно `?action=ping` |
| `{"ok":false,"error":"server_error"}` | Внутренняя ошибка скрипта | Откройте «Выполнения» («Executions») в редакторе Apps Script и посмотрите текст ошибки |

Если ответ пришёл в виде HTML-страницы входа в Google, значит развёртывание сделано с доступом не «Все» — переделайте шаг 6.
